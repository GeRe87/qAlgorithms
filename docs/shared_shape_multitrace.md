# qAlgorithms: shared-shape multi-trace regression

## Model and design

For m aligned log-intensity traces and a window of n = 2h+1 equidistant
samples with x = -h, ..., 0, ..., h, the new regression fits

\[
y_j(x) = b_{0,j} + b_1x +
\begin{cases}b_2x^2 & x<0\\ b_3x^2 & x\ge 0.\end{cases}
\]

Every trace has a separate intercept, but all traces share b1, b2 and b3.
For each scale, qAlgorithms already stores the six unique entries of the
single-trace inverse in qalgo_matInverse[scale], ordered A, B, C, D, E, F:

~~~
      b0  b1  b2  b3
b0     A   0   B   B
b1     0   C   D  -D
b2     B   D   E   F
b3     B  -D   F   E
~~~

These values are generated by external/qalgorithms_matinverse.c for scales
2 through 215. This table remains unchanged.

## Exact inverse for arbitrary m

The enlarged inverse, in parameter order
(b0_1, ..., b0_m, b1, b2, b3), needs only seven unique nonzero values,
counting sign changes and symmetric placements as the same value:

| Value | Position | From the existing cache |
|---|---|---|
| A1 | Each intercept diagonal | 1/n + (A - 1/n)/m |
| A2 | Each pair of different intercepts | (A - 1/n)/m |
| Bm | Intercept versus either curvature | B/m |
| Cm | b1 versus b1 | C/m |
| Dm | b1 versus b2; negative for b1 versus b3 | D/m |
| Em | b2 versus b2 or b3 versus b3 | E/m |
| Fm | b2 versus b3 | F/m |

Intercept-to-slope entries are zero. For m=1 this reduces to the original
4 x 4 inverse (A2 has no position). The new
sharedShapeInverseForScale(h,m) returns these seven values in a fixed
structure, without allocating the (m+3) x (m+3) matrix.

## Fitting with six cached values

Let s_j be the sum of the observations in trace j over the current window,
u0 = (sum_j s_j)/m, and u1, u2, u3 be the corresponding averaged sums
of x*y, x^2*y on the negative side, and x^2*y on the positive side.
Then the exact least-squares estimates are

~~~
meanB0 = A*u0 + B*(u2+u3)
b1     = C*u1 + D*(u2-u3)
b2     = B*u0 + D*u1 + E*u2 + F*u3
b3     = B*u0 - D*u1 + F*u2 + E*u3
b0_j   = meanB0 + (s_j-u0)/n
~~~

Equivalently, the shared shape equals the ordinary regression of the
pointwise *mean trace*. The separate intercepts are the mean intercept
plus each trace's window-mean offset. This equivalence holds exactly
for aligned, unweighted traces.

The streaming forEachSharedShapeCoefficients API follows the existing
running-sum strategy, updating all trace-specific intercept sums and the
three shared weighted sums as the scale grows. Scratch memory is O(m);
the inverse cache stays at **six doubles per scale**, and work per fit is
O(m). Its visitor receives a reused result object in centre-major order.

findSharedShapeCoefficients collects the same results in scale-major order,
matching the pre-existing findCoefficients API. Collecting all intercepts
across all candidate windows naturally uses O(m * windows) memory.

## Integration boundaries and tests

- The sample at x=0 is included in the intercept sum. Its contributions
  to the three other design columns are zero.
- All traces must use identical sample coordinates, valid samples and equal
  weights. Different x grids, missing values or different weights require
  a different normal matrix.
- The residual degrees of freedom for a complete window are m*n-(m+3),
  not m*n-4. The existing qPeaks downstream tests, variance propagation
  and intensity-domain b0 correction are **not** modified by this module.
- The new test/test_qpeaks_multitrace.cpp constructs and inverts the
  full design independently, checks the seven-entry inverse and solves
  the normal equations for m=1,2,3,10 and h=2,3,8,25,100,215. It also
  verifies result ordering and invalid-input handling.
